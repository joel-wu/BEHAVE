# Task interface files

The `contract` submission argument is a workspace-relative **file path**,
for example `contract.json`. Write the JSON file first. Do not pass prose, inline
JSON, an absolute path or a Python filename as this argument.

This directory includes complete examples generated by the current Sim API:
`contract_ready_valid.json` (accepted ready/valid transactions),
`contract_sampled_edge.json` (plain pins sampled at every non-reset clock edge)
and `contract_settled.json` (clockless combinational). Copy an appropriate example to your own contract file
and adapt it to the task. They illustrate serialization, not required widths,
protocols, state behavior or task restrictions. Preserve the task's intended
interface; other supported protocols, multiple endpoints/clocks and memories
can be declared in the public contract format.

Derive transaction boundaries and output counts from the task, not the example.
`answers_per_transaction` counts outputs per accepted input transaction, not per
frame or Python call. Do not copy a fixed one-to-one count for a different or
variable-length relationship, or simplify the task to fit it. Use a supported
declaration; report an unsupported relationship rather than misdeclaring it.

The JSON represents `behave.sim.api.TaskContract.as_dict()`. Keep its complete
field structure and current version; an informal object containing only port
names is not a TaskContract. The shell does not provide an importable `behave`
package. Edit the supplied JSON and check it with your Behavior through
`python /tools/behave_sim_check.py check.json`, as described in `sim_check.md`.
JSON parsing checks serialization, not executable protocol compatibility.

For single-entry reference replay, Sim calls `process` with each input field's
declared payload `port` as a keyword argument. Returned records use the output
payload `port` names too. The examples give each field the same `name` and
`port`. A reset event calls `reset()` on the model;
a constructor alone does not implement reset. Define both methods and document
their signatures in the Behavior interface. This stateless identity model is a
minimal executable example for the supplied contracts, not a solution to your
task:

```python
class Model:
    def reset(self):
        pass

    def process(self, in_x):
        return {"out_y": in_x}
```

For stateful tasks, reset must restore the specified state. A no-op model reset
does not add a hardware reset to a clockless task. With `sampled_edge`, each call
represents a non-reset edge, including edges without a data transfer. Put the
sampled pin values in the fields and specify pre-edge output visibility. Do not
replace that interface with accepted-transaction ready/valid semantics.

Every declared payload field in an observed output record is compared. In the
ungated sampled-edge example, a payload field named `valid` is ordinary data,
not an adapter control: other output fields are still compared when it is zero.
Signal names and prose do not create per-field or packed-lane comparison masks.
If an output is genuinely unobserved, express that with a supported contract;
otherwise specify its exact value, including idle cycles. Do not declare data
unspecified while relying on one model's chosen value for exact comparison.

Adapter control names are literal RTL signal names, not abstract roles. Independent
input endpoints need separate presentation-control pins (for ready/valid,
separate valid pins); copying an endpoint also requires updating these names.
The ready/valid example uses `in_valid/in_ready` and `out_valid/out_ready`.
Adapt these bindings if your RTL declaration uses different names; the logical
endpoint name does not rename a physical pin.

Endpoint directions are from the environment's viewpoint: `in` supplies task
inputs and `out` observes results. Declare finite field widths/signedness, signal
bindings, handshake ownership, clock/reset, output ordering and output count.
Field signedness must match the RTL declaration: a signed input needs an
explicit declaration such as `input logic signed [15:0] in_x`. Describing an
unsigned vector as two's complement in prose does not change its declared type.
Set each field's `port` explicitly to its physical RTL payload signal name. If
you rename `in_x`'s port to `in_data`, also use `process(self, in_data)`. If you
rename `out_y`'s port to `out_data`, return `{"out_data": value}`. Changing only
the contract leaves the reference call interface inconsistent. Document these
signatures and the exact Behavior return shape in the specification. The
contract declares observations and protocol, not the task's algorithm.

Ordinary task submission instantiates the reference with its default constructor
arguments. Prose does not supply per-run constructor settings or tie extra RTL
pins. Bind every required external signal through the executable interface;
do not assume an unsubmitted testbench will drive it. If the required configuration
cannot be expressed, report that gap rather than silently dropping the behavior.

For task-author submission, `run_policy` is also a file path. For an ordinary
task write `null` as that file's entire JSON value. This selects the evaluator's
runtime generation settings. Do not invent per-task test counts, lengths or
execution/search budgets. `GenerationSpec` describes runtime schedule quantities,
not allowed payload values or cross-cycle input constraints. Stating a legal-input
restriction in the specification does not configure the generator. Do not claim
such a restriction is enforced without an executable declaration that supports it;
report any required but unsupported input-domain constraint for review.
