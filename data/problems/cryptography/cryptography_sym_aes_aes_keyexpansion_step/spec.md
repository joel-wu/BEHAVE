# AES Key Expansion Step

This block computes the first four new 32-bit words at a group boundary of the AES encryption key schedule. The selected group size is 4, 6, or 8 words; the supplied previous words and round-constant index determine the result. It is a recurrence suboperator, not a complete AES-192 or AES-256 key expander.

## Interface

### RTL interface

```systemverilog
module cryptography_sym_aes_aes_keyexpansion_step (
    input  logic         clk,
    input  logic         rst,

    input  logic         in_valid,
    output logic         in_ready,
    input  logic [1:0]   in_key_words,
    input  logic [3:0]   in_rcon_idx,
    input  logic [31:0]  in_w0,
    input  logic [31:0]  in_w1,
    input  logic [31:0]  in_w2,
    input  logic [31:0]  in_w3,
    input  logic [31:0]  in_w4,
    input  logic [31:0]  in_w5,
    input  logic [31:0]  in_w6,
    input  logic [31:0]  in_w7,

    output logic         out_valid,
    input  logic         out_ready,
    output logic [2:0]   out_words_valid,
    output logic [31:0]  out_w0,
    output logic [31:0]  out_w1,
    output logic [31:0]  out_w2,
    output logic [31:0]  out_w3
);
```

`in_key_words` encodes the AES key length:
- `2'b00`: Nk = 4 words, AES-128
- `2'b01`: Nk = 6 words, AES-192
- `2'b10`: Nk = 8 words, AES-256
- `2'b11`: reserved; treated identically to `2'b00`

### Behavior interface

```python
class CryptographySymAesAesKeyexpansionStep:
    def __init__(self): ...
    def reset(self): ...
    def process(
        self,
        in_key_words,
```

The returned dict contains keys:
`out_words_valid`, `out_w0`, `out_w1`, `out_w2`, `out_w3`.

Return exactly one dictionary on every call, never None or a list. All fields are
present even when a valid or status flag is zero.
Every returned dictionary contains exactly these fields (bit widths):

- `out_w0`, `out_w1`, `out_w2`, `out_w3`: 32.
- `out_words_valid`: 3.

Arguments and returned fields are nonnegative integers of their declared port
widths. Signed quantities use two's-complement bit encodings.
Supply all named process arguments on each call. Reuse the instance across
the input sequence. `reset()` establishes the specified initial model state,
returns `None`, and emits no record.

## Modules

- `cryptography_sym_aes_aes_keyexpansion_step`: top module implementing one AES encryption key-schedule recurrence step.

## Functional Behavior

Transfers occur on rising clock edges with `rst = 0`: an input is accepted when `in_valid && in_ready`, and an output is consumed when `out_valid && out_ready`. The sender holds `in_valid` and all input payload fields stable while waiting for `in_ready`; the block likewise holds `out_valid` and all output payload fields stable under output backpressure. Responses preserve accepted-input order. Reset cancels all outstanding transactions; no pre-reset response may appear after reset. No fixed latency or pipeline topology is required.

All words are 32-bit unsigned integers. Byte numbering within a word is big-endian: for word `x`, byte 3 is `x[31:24]`, byte 2 is `x[23:16]`, byte 1 is `x[15:8]`, and byte 0 is `x[7:0]`.

The module is stateless at the architectural level. Each accepted input transaction independently computes one output transaction.

The round-constant table is:
- `rcon[0] = 0x01000000`
- `rcon[1] = 0x02000000`
- `rcon[2] = 0x04000000`
- `rcon[3] = 0x08000000`
- `rcon[4] = 0x10000000`
- `rcon[5] = 0x20000000`
- `rcon[6] = 0x40000000`
- `rcon[7] = 0x80000000`
- `rcon[8] = 0x1B000000`
- `rcon[9] = 0x36000000`

`in_rcon_idx` addresses this 10-entry table. If `in_rcon_idx` is greater than 9, the round constant used is `0x00000000`.

Define `rot_word(x) = ((x << 8) | (x >> 24)) mod 2^32`. `sub_word(x)` substitutes each byte without moving it:

- `sub_word(x) = (SBOX[x[31:24]] << 24) | (SBOX[x[23:16]] << 16) | (SBOX[x[15:8]] << 8) | SBOX[x[7:0]]`.
- Consequently, `sub_word(rot_word(x))` substitutes the bytes in the order `x[23:16], x[15:8], x[7:0], x[31:24]`.

The output depends on `Nk`, selected by `in_key_words`.

### AES-128 mode (`Nk = 4`, `in_key_words = 2'b00` or `2'b11`)

Inputs used: `in_w0`, `in_w1`, `in_w2`, `in_w3`.

Compute:
- `g = sub_word(rot_word(in_w3)) XOR rcon[in_rcon_idx]`
- `new0 = in_w0 XOR g`
- `new1 = in_w1 XOR new0`
- `new2 = in_w2 XOR new1`
- `new3 = in_w3 XOR new2`

Outputs:
- `out_words_valid = 3'd4`
- `out_w0 = new0`
- `out_w1 = new1`
- `out_w2 = new2`
- `out_w3 = new3`

### AES-192 mode (`Nk = 6`, `in_key_words = 2'b01`)

Inputs used: `in_w0`, `in_w1`, `in_w2`, `in_w3`, and `in_w5`. `in_w4`, `in_w6`, and `in_w7` do not affect this mode's four outputs.

Compute:
- `g = sub_word(rot_word(in_w5)) XOR rcon[in_rcon_idx]`
- `new0 = in_w0 XOR g`
- `new1 = in_w1 XOR new0`
- `new2 = in_w2 XOR new1`
- `new3 = in_w3 XOR new2`

Outputs:
- `out_words_valid = 3'd4`
- `out_w0 = new0`
- `out_w1 = new1`
- `out_w2 = new2`
- `out_w3 = new3`

The remaining AES-192 schedule words `in_w4 XOR new3` and `in_w5 XOR (in_w4 XOR new3)` are not produced by this block.

### AES-256 mode (`Nk = 8`, `in_key_words = 2'b10`)

Inputs used: `in_w0`, `in_w1`, `in_w2`, `in_w3`, and `in_w7`. `in_w4` through `in_w6` do not affect this half-step.

Compute the first half-step:
- `g = sub_word(rot_word(in_w7)) XOR rcon[in_rcon_idx]`
- `new0 = in_w0 XOR g`
- `new1 = in_w1 XOR new0`
- `new2 = in_w2 XOR new1`
- `new3 = in_w3 XOR new2`

Outputs:
- `out_words_valid = 3'd4`
- `out_w0 = new0`
- `out_w1 = new1`
- `out_w2 = new2`
- `out_w3 = new3`

This block does not produce the second AES-256 half-step (`w[i+4]` through `w[i+7]`) derived from `sub_word(new3)`.

All XOR operations are 32-bit bitwise XOR with wrap modulo `2^32`. All output words are the exact 32-bit results of these expressions.

## Reset Behavior

Reset is synchronous active-high `rst`.

Architectural state: none.

After reset, the module is ready to accept an input transaction. Output interface state after reset:
- `in_ready = 1`
- `out_valid = 0`
- `out_words_valid = 3'd0`
- `out_w0 = 32'h00000000`
- `out_w1 = 32'h00000000`
- `out_w2 = 32'h00000000`
- `out_w3 = 32'h00000000`
