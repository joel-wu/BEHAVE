# SHA-256 Message Schedule

This module expands one 512-bit SHA-256 message block into the 64 32-bit schedule words `W[0]` through `W[63]` defined by FIPS 180-4. The first 16 words are loaded from the input block in big-endian byte order, and words 16 through 63 are generated by the SHA-256 message-schedule recurrence using the lowercase sigma functions `σ0` and `σ1`. Each accepted input transaction produces 64 output transactions in order, one schedule word per output beat.

## Interface

### RTL interface

```systemverilog
module cryptography_sym_sha_sha256_msg_schedule (
    input  logic         clk,
    input  logic         rst,

    input  logic         in_valid,
    output logic         in_ready,
    input  logic [511:0] in_block,

    output logic         out_valid,
    input  logic         out_ready,
    output logic [5:0]   out_index,
    output logic [31:0]  out_word
);
```

### Behavior interface

```python
class CryptographySymShaSha256MsgSchedule:
    def __init__(self): ...
    def reset(self): ...
    def process(self, in_block): ...
```

`process()` returns a `list[dict]` of length 64. Each dict contains keys `out_index` and `out_word`.

Return a list of exactly 64 dictionaries, in increasing out_index order from 0 through
63. Never return None or a bare dictionary.
Every returned dictionary contains exactly these fields (bit widths):

- `out_index`: 6.
- `out_word`: 32.

Arguments and returned fields are nonnegative integers of their declared port widths.
Signed quantities use two's-complement bit encodings.
Supply all named process arguments on each call. Reuse the instance across
the input sequence. `reset()` establishes the specified initial model state,
returns `None`, and emits no record.

## Modules

- `cryptography_sym_sha_sha256_msg_schedule`: top-level module that accepts one 512-bit block and emits the 64 SHA-256 schedule words for that block.

## Functional Behavior

Transfers occur on rising clock edges with `rst = 0`: an input is accepted when `in_valid && in_ready`, and an output is consumed when `out_valid && out_ready`. The sender holds `in_valid` and all input payload fields stable while waiting for `in_ready`; the block likewise holds `out_valid` and all output payload fields stable under output backpressure. Responses preserve accepted-input order. Reset cancels all outstanding transactions; no pre-reset response may appear after reset. No fixed latency or pipeline topology is required.

`in_block` is a 512-bit unsigned value carrying a SHA-256 message block as 64 consecutive bytes in network order. Byte 0 is `in_block[511:504]`, byte 1 is `in_block[503:496]`, ..., byte 63 is `in_block[7:0]`.

For `i = 0..15`, the initial schedule words are formed from the input block in big-endian byte order:

- `W[i] = concat(byte[4*i+0], byte[4*i+1], byte[4*i+2], byte[4*i+3])`

Equivalently, using bit slices of `in_block`:

- `W[0]  = in_block[511:480]`
- `W[1]  = in_block[479:448]`
- ...
- `W[15] = in_block[31:0]`

All schedule words are 32-bit unsigned integers. Every addition in the recurrence below wraps modulo `2^32`.

Define 32-bit rotate-right and logical-right-shift operations:

- `ROTR_n(x) = ((x >> n) | (x << (32 - n))) mod 2^32`
- `SHR_n(x)  = x >> n`

Define the SHA-256 lowercase sigma functions:

- `σ0(x) = ROTR_7(x) XOR ROTR_18(x) XOR SHR_3(x)`
- `σ1(x) = ROTR_17(x) XOR ROTR_19(x) XOR SHR_10(x)`

For `i = 16..63`, compute:

- `W[i] = (σ1(W[i-2]) + W[i-7] + σ0(W[i-15]) + W[i-16]) mod 2^32`

One accepted input transaction produces 64 output transactions in increasing index order. Output beat `i` carries:

- `out_index = i` as a 6-bit unsigned value
- `out_word  = W[i]` as a 32-bit unsigned value

No other outputs are produced for that input.

## Reset Behavior

Reset is synchronous active-high.

Architectural state after reset:

- No pending output words are stored.
- The module is able to accept a new input block.
- There is no retained state from any earlier input transaction.

Output port values during reset or while no output transaction is being presented:

- `out_valid = 0`
- `out_index = 6'b000000`
- `out_word = 32'b00000000000000000000000000000000`

When the module is idle and able to accept a new input transaction, `in_ready = 1`.
